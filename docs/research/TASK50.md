## 핵심 발견

1. **`stack` — 무처치 반복의 채널 불일치는 0이 아니며, 이 substrate에서 45쌍
   중앙값 0.0062–0.0184 · 95 분위 0.0320–0.0604다.** 값은 이 stack의 오버헤드
   구조에 딸린 상수다.
2. **`class` — 두 채널의 재현성은 비대칭이며, 모형 기반 채널이 모형 무의존 채널보다
   훨씬 재현성이 높다.** A′의 CV는 0.0004–0.0077, B는 0.0099–0.0215로 N=6에서
   **50배** 차이다. 형태가 클래스인 이유: A′는 계획된 작업량(step 열·계산 token)을
   비용 모형으로 환산하므로 같은 trace면 거의 같은 값이 나오고, B는 queueing·HTTP·
   프로세스 기동 상태를 그대로 담기 때문이다. 이 분업은 특정 구현이 아니라 "모형
   재구성 대 벽시계 관측"이라는 채널 설계 범주에서 나온다. **값(50배, 0.0004)은
   인스턴스 상수이므로 이식하지 않는다.**
3. **`stack` — 무처치인데도 채널 A′가 이산적으로 변한다.** N=8에서 A′는 5개 값만
   갖고, 그중 12.897 s인 3회(rep 1·6·9)는 정확히 **재사용이 6/8이 아니라 5/8인
   회차**다. 같은 trace를 같은 구성으로 다시 돌려도 세션 하나의 캐시 생존 여부가
   바뀐다. 다만 이 이산 사건이 gap을 키우지는 않았다 — 재사용이 같은 24쌍의 중앙
   gap이 0.0078, 다른 21쌍이 0.0047로 오히려 반대다.
4. **`universal` — 허용차를 검증하려면 판정과 같은 집계 단위에서 null을 재야 한다.**
   1-run 짝과 3-run 집계 짝의 95 분위가 N=6에서 0.0604 대 0.0326, N=8에서 0.0320 대
   0.0167로 **약 2배** 다르다. 같은 자료·같은 정의인데 집계 단위 하나로 분류가
   C3→C2, C2→C1로 바뀐다. 선등록이 이 점을 놓쳤다.

## 해석

관찰과 분리해 적는다. 아래는 파생 해석이며 판정이 아니다.

- 선등록 산출(1-run 짝)만 보면 N=6에서 `q95 > τ_null`이지만, 그 짝은 판정이 쓰는
  집계 단위가 아니다. 판정과 같은 3-run 집계에서는 두 N 모두 `q95 ≤ τ_null`이다.
  **어느 쪽을 허용차의 기준으로 삼을지는 이 TASK가 결정하지 않는다.**
- N=6의 null이 N=8보다 넓은 것을 N 효과로 읽을 수 없다. N=6 trace의 tool gap 총량이
  0.140 s여서 run이 8.2 s로 짧고 고정 오버헤드가 차지하는 몫(r/B 중앙 0.0534)이
  크다. N과 gap 총량이 함께 달라졌으므로 **교란**이다.
- P1–P4가 빗나간 방향은 일관되게 "예측보다 넓다"이다. 예측 근거였던
  [TASK36](TASK36.md)·[TASK40](TASK40.md)의 실측 채널 차 0.0001–0.0068은 3블록
  합에서 나온 값인데, 예측은 그것을 1-run 짝의 상한처럼 썼다. 발견 4와 같은 실수다.

## 확인되지 않은 사항

- **N당 trace가 하나이므로 null 폭이 trace에 얼마나 의존하는지 모른다.** 반복이
  설계의 핵심이라 trace를 고정한 결과이며, 다른 trace에서 같은 폭이 나오는지는
  측정하지 않았다. `UNKNOWN`.
- **N 효과와 gap 총량 효과가 분리되지 않는다** (위 해석 참조). `UNKNOWN`.
- 측정 중 host의 다른 부하를 통제·기록하지 않았다. 채널 B의 변동 중 host 부하에서
  온 몫은 `UNKNOWN`이다.
- rep 7(N=6, B = 8.637 s, r/B = 0.1055)과 rep 5(N=8, B = 13.612 s)가 다른 회차보다
  뚜렷이 크다. 원인은 확인하지 않았다. `UNKNOWN`.
- 이 결과가 `batch_size` 16 이상 구성이나 다른 N에서도 같은지는 측정하지 않았다.
