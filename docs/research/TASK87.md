1. **`stack`** — **고부하에서 구성 선택의 효과가 25 %로 커지고(BASE 대비 비 0.70–0.80), 순위는 세 예측기 모두 맞혔으나 크기는 모두 과소 예측했다.** v1.1이 가장 가깝다(Σ\|오차\| 0.087 대 sim 0.189, v1 0.358). BASE의 turn당 비용은 v1.1(+1.3–1.6 %)과 sim(0 %)이 맞히고 v1은 크게 과소(−4 %, −8 %)했다.
2. **`stack`** — **v1.1은 대기열 영역의 BASE 재사용을 과소 예측했다**(N14 0.173 대 0.298, N16 0.068 대 0.165). 결합·대기 항이 축출을 과대 계상한다. v1은 반대로 과대(N16 0.305). 관측은 둘 사이, 시뮬레이터 쪽이다.

## 해석

- **사전 예측 대비**: v1.1의 §5.1 FAIL과 v1.1 대 v1 FAIL, 그 방향(비는 v1.1, 재사용은 v1)이 모두 적중했다. 틀린 것은 sim 대리 가정의 크기다 — 관측 BASE 재사용은 sim보다 약간 낮았다(0.298 대 0.330, 0.165 대 0.191).
- **v1.1이 무엇을 과대 계상했나(가설)**: (a) 완료 순서의 극단(admission, 먼저 온 요청이 반드시 먼저 끝남)이 대기열에서는 older 항목을 너무 빨리 inactive로 만들어 결합 할당에 먹히게 한다 — random과 admission 사이의 중간 순서가 필요할 수 있다. (b) R 대기 중 새 도착은 R 뒤에 선다고 두었으나 즉시 복귀(zero gap) 세션의 정확한 위치, (c) B2가 BASE 평균 running을 과대(6.95 대 6.28, 7.55 대 6.87) 예측해 대기열 깊이를 과대했다 — 결합·대기 항이 과대된 대기열 위에서 계산됐다. (c)는 v1도 같은 방향(6.74, 7.33)이라 B2 공통 문제다.
- 개발 집합(N = 12)에서 v1.1은 BASE를 −0.048 과소했고, N14·16에서 −0.125·−0.097로 과소가 커졌다. 개발 집합의 편향 방향이 blind에서 유지·확대됐다.
- §5.2 v1.1의 FAIL은 한 cell(TUNED N16)의 0.006 초과로 났다. skill 비는 0.09로 영 예측기의 1/11이다 — "틀리지 않았다"보다 "크기를 조금 과소"가 정확한 서술이다. 기준은 완화하지 않는다.
