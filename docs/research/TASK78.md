## 목적

Advisor 지시문 04 작업 B. multi-turn 본 실험에 넣을 N별 격자를 **측정된 h가 아니라 모형이 예측한 h로** 고른다(blind). 해석 경로(주)와 시뮬레이터 경로(보조)를 모두 계산하고, 규칙에 따라 compile 대상을 정한다.

**판정: 규칙의 멈춤 조건에 걸렸다.** 해석 경로 격자가 네 N 모두에서 TUNED와 다르고 서로도 달라 새 compile이 **4개**다. 지시문 "새 compile이 최대 3개를 넘으면 멈추고 보고한다"에 따라 **compile을 하지 않았다.** 선정 결과만 기록하고 결정을 Advisor에게 올린다. 그래서 상태가 `PARTIAL`이다.

## 수행 내용

1. N ∈ {6, 8, 10, 12}마다 plan 3개를 본 실험과 같은 생성 규칙·**다른 seed**(`20261200 + 10N + r`)로 만들었다. `cycle_s`는 해석 모형(TUNED) 예측.
2. **해석 경로**: plan 통계 → B2(곱 형태 + prefill 고정점) + v1 생존(재사용과 E[P] 결합 고정점) → step 가중 h → B3 DP(`batch_size` 16, 격자 ≤ 6). TUNED에서 시작해 "격자 → 예측 h → DP 격자"를 고정점까지 반복.
3. **시뮬레이터 경로**: 같은 plan을 기본 의미론 시뮬레이터(세션 갱신 옵션)에 넣고 평가 구간 h → DP, 같은 반복.
4. compile 규칙 적용: 해석 경로 격자가 TUNED와 다르면 대상. 새 격자 4개 → 상한 초과 → 멈춤.

## 핵심 발견

1. **`stack`** — **steady-state multi-turn 부하에서 모형이 예측한 running 분포는 원고 조건보다 훨씬 낮은 n에 몰리고, 그래서 최선 격자가 원고 선정 G\*(1,4,6,8,10,16)와 크게 다르다** — 작은 폭(2·3·4·5)이 들어온다. tool gap(평균 4.2 s)이 서비스 시간(약 2 s)보다 길어 동시 running이 N의 30–45 %에 머물기 때문이다. 값은 이 인스턴스의 것이다.
2. **`stack`** — **예측 이득은 작다**: TUNED 대비 격자 의존 비용 1.8 % (N=6) → 0.65 % (N=12). 이것은 decode padding 항의 비율이므로 turn당 전체 device time에 대한 이득은 더 작다.
3. **`universal`** — 두 경로가 N=8·10에서 같은 격자를 내고, N=6·12에서 인접 격자(한 폭 차이)로 갈린다. N=12 시뮬레이터 경로는 최선 응답 반복이 **순환**했다 — 격자–h 되먹임이 고정점을 보장하지 않는다는 [MODEL_V0.md](MODEL_V0.md) B3 (iv)의 사례다.

## 해석

- 예측 이득이 1 % 안팎이면, replicate 5회의 본 실험에서 DP 격자 대 TUNED의 차를 CI로 가를 수 있을지 불확실하다(파일럿 결과로 run 간 변동을 보고 판단해야 한다). 이 점이 compile 대상 결정에 들어가야 한다.

- 예측 이득이 측정 해상도보다 큰지
