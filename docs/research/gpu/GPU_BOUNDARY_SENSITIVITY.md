# 비용 집계의 경계 효과 민감도 — GPU (G-09 작업 A, GTASK22)

판정 종류: **post_hoc**. 측정 0, GTASK11·GTASK20 run 로그와 commit된 plan·예측 파일만 읽음. 새 예측·모형·시뮬레이터 수정·기존 판정 변경 없음. NPU 대응: [TASK111](../TASK111.md), `paper/BOUNDARY_SENSITIVITY.md`.
스크립트: `experiments/gpu/multiturn/boundary_sensitivity.py` → `results/gpu/multiturn/boundary/boundary_sensitivity.json`(ignored raw), 표 `boundary_tables.py`.

## 1. 정의

| 항목 | 정의 |
|---|---|
| 관측 A′-GPU/turn (창 L, bound β) | 같은 w0, w1 = w0 + L. `w0 ≤ sent_s < w1` 요청 Q의 첫·마지막 `[GPFX] ALLOC` 줄 사이 모든 `[GSTEP]` k에 대해 `Σ step_ms(d_k, p_k, grid, β) / |Q|`. d_k = `reqs`(`maxq = 1`) 또는 `reqs − max(1, 직전 step 이후 ALLOC 줄 수)`, p_k = `toks − d_k`. `gpu_mt_measure.lifecycle_metrics`와 같은 식 |
| 관측 비 | 같은 replicate 구성/BASE의 중앙값(k = 5, verdict `used`의 lifecycle, 재실행 0) |
| 예측 비 (창 L) | 주 예측기를 commit된 예측 파일과 같은 코드 경로·입력으로 다시 돌려 시작 시각이 [w0, w1)인 simulated step·도착이 [w0, w1)인 요청으로 집계, plan 5개 합산 비. GTASK11 `sim_lru`(`predict_mt.sim_cell`: step duration 합 = 가격), GTASK20 `ctx`(`predict_blind.run_one`: context 비용으로 시간 진행, step 가격 합) |
| 재현 점검 | L = 120에서 관측 replicate 비 22/22 행이 verdict(`5.2.<β>.observed.<N>/<구성>.ratios`, N26은 `N26.POOL/BASE.<β>.ratios`)와, 예측 비 22/22 행이 예측 파일 `ratio_to_base`와 **정확히 같다**(Python 3.12.13 venv; §3.6) |
| 창 길이 | 60·90·120 s. 150 s 이상은 불가: runner가 w0 + 120 s에서 발행을 멈춘다(`eval_s = 120`) |
| 대상 | GTASK11 N20·22·24 × {POOL, POOL+GRID}/BASE, N26(탐색) POOL/BASE; GTASK20 N25·28 × {POOL, POOL+GRID}/BASE. 비 11 cell × bound 2 = 22 행 |
| step 구성원 (작업 B) | GTASK12 step 진행 규칙(`replay.py`, block pool 제외): ALLOC 줄이 그 요청을 `scheduled` 토큰과 함께 넣고, 이후 schedule마다 마지막 token이 아직 schedule되지 않은 running 요청이 admission 순서로 `prefill 중이면 min(prompt − computed, 남은 budget 2048)`, 아니면 1 token을 받는다. 재구성 (구성원 수, token 수) = (`reqs`, `toks`): 첫 ALLOC 이후 802,567/802,567 step 일치(첫 ALLOC 이전 server warm-up step 170개 = lifecycle당 2개, 요청 없음) |
| step 가격의 prefill·decode 분할 | A′-GPU 가격 P_k = `step_ms(d_k, p_k)` 그대로. decode 몫 = `decode_ms(d_k)`(d_k ≥ 1, 재구성 decoder에게 균등), prefill 몫 = P_k − decode 몫(재구성 prefill 구성원에게 그 step token 수 비례; d_k = 0이면 P_k 전체). `gpu_cost` 정의상 prefill 몫 = `prefill_increment_ms`(PIECEWISE [0, 1.5] ms, eager는 p 보간), 즉 A′-GPU의 간섭 항과 같은 분할이다 |
| A′ 규칙 d_k ≠ 재구성 decoder 수 | 139/802,567 step(0.017 %): 이어지는 prefill chunk(ALLOC 줄 없음)와 새 admission이 한 step에 있으면 규칙이 decoder를 1개 더 센다(`gpu_mt_measure` docstring의 기존 규칙). 이 step도 가격은 규칙 (d_k, p_k) 그대로, 분할만 재구성 구성원 기준 |
| 시작 잔여 S | A′-GPU step 범위 안에서, w0 이전 발행 요청이 차지한 몫 |
| 끝 잔여 E | 마지막 평가 요청 ALLOC 줄 이후 step에서, 평가 요청이 차지한 몫(남은 decode와, 범위 밖에 놓인 마지막 admission step의 prefill 포함) |
| 보정 A′-GPU | (A′-GPU 총합 − S + E) ÷ 요청 수. 보정 비 = 같은 replicate 보정 A′-GPU 비 |
