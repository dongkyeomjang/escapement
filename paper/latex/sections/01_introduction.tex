\section{Introduction}
\label{sec:01}

Agentic workloads interleave LLM calls with tool execution. A session issues a request, receives a response, runs a tool, and comes back. The serving cost of such a workload is not set by the requests alone: it is set by \textbf{when the sessions come back}, because that arrival process decides how many of them are resident at once, and residency is what the accelerator prices.
% CLAIMS 1.1, 1.5, 1.8

This paper decomposes that return-arrival process on real hardware --- an RBLN CA25 NPU running \texttt{vllm 0.22.0} with \texttt{vllm-rbln 0.11.1} and artifacts built by \texttt{optimum-rbln 0.11.1} --- and finds three mechanisms that turn it into device time. None of the three responds to a property of an individual request; all three respond to a \emph{collective} property of arrivals.
% CLAIMS 1.1, 1.5, 1.8

The substrate is one instance of a broader class rather than a curiosity. Accelerators that fix tensor shapes when the model is built, and therefore enumerate a \textbf{discrete set} of them, include AWS Inferentia --- where input shape is fixed at compile time and bucketing is the documented remedy for variable sizes --- and Intel Gaudi, whose graph compiler prefers static shapes and recompiles when they change. The same discreteness appears inside GPU serving stacks as the enumerated CUDA-graph capture sizes, and Section~\ref{sec:07} shows from the serving stack's own source that the alignment law studied here does \textbf{not} vanish there. What follows is measured on one member of that class; which statements are about the class and which about the member is marked throughout.
% CLAIMS 4.1, 4.2

First, the accelerator does not decode an arbitrary batch width: it rounds the running set up to one of a \textbf{discrete set of compiled widths}. Whether the offered concurrency lands on a rung or between two rungs decides not merely the size but the \textbf{sign} of the effect that a tool gap has. We establish this causally rather than by correlation, with a recompile that changes only the grid and holds workload, seed, model and slot count fixed.
% CLAIMS 1.5
% CLAIMS 1.6

Second, completed prefixes live in a pool of \textbf{sequence-granular slots}, and when the pool is full the oldest allocation is evicted whole. Survival is therefore a cliff rather than a slope, and its threshold counts \emph{requests}, not tokens. On this instance the reuse of a completed prefix survives six background requests and disappears at the seventh, because the layer-2 pool holds eight outer slots of 8,192 tokens each under FIFO; the threshold is \texttt{8 $-$ 1 $-$ 1}, and it reproduced 12/12 deterministically.
% CLAIMS 1.1
% CLAIMS 1.2

Third, prefill runs \textbf{exclusively}: while one session recomputes a prefix, every other session's decode is stopped for the full duration. The cost of a cache miss is therefore not that session's latency but recomputation time multiplied by the number of concurrent decoders. This is where the first two mechanisms multiply: the grid decides how wide the batch is, the slot pool decides who has to recompute, and exclusive prefill charges the recomputation to everyone.
% CLAIMS 1.8

\subsection{Position with respect to prior work}

Two of the ideas this paper stands on are already in the literature. \textbf{LENS} \cite{lens2026} makes explicit that an NPU's discrete bucket grid renders latency non-linear, and makes that non-linearity predictable; \textbf{AgentServeSim} \cite{agentservesim2026} builds a simulator for multi-turn agent serving --- KV residency across tool gaps included --- precisely because the policy space is too large to measure. Neither treating the grid as a first-class object nor simulating agent serving originates here. The two stop on different axes, however. LENS sees the grid but sees \emph{one request}, so the axis along which one session's KV-slot occupancy decides \emph{another} session's cache survival is undefined in its model. AgentServeSim sees multi-session dynamics but targets a \textbf{dynamic GPU runtime} --- continuous batching, tunable reclaim, a memory hierarchy --- and so does not ask what remains when reclaim is a sequence-granular FIFO frozen at compile time. \textbf{This paper sits at the intersection}: an NPU's compile-static grid meeting a multi-session arrival process. That the intersection was empty is what left room for this work, and it is where four fifths of the device time we recover comes from: the chain from \texttt{batch\_size} to KV slot count to cache survival to prefill recomputation appears neither in a single-request model nor in one that presumes reclaim policy can be changed. Our simulator's contribution is likewise not that a simulator exists, but that it predicts the device time of a configuration \textbf{that has not yet been compiled, with zero fitted parameters, from predictions committed before measurement} --- which is the only thing that licenses taking device measurement out of the selection loop.

\subsection{What this paper reports}

On top of the three mechanisms we build a step-level model with \textbf{no fitted parameters}, and put its predictions through preregistered gates: it reproduces eighty previously measured combinations, then predicts out-of-sample cells committed before measurement, then predicts cells in which a control intervention was applied, then survives a change of the gap distribution itself.
% CLAIMS 1.14, 1.15, 1.16, 1.17

With that model we obtain a \textbf{negative result}, and it is the reason the paper's positive result takes the shape it does. Rescheduling return times leaves real offline headroom, but a median 60 \% of that headroom is \emph{coordination}: give every session omniscient knowledge and let each decide independently, and that share disappears. \textbf{No per-session runtime policy can reach it, in principle.} Nor is the remainder reachable in practice: the value of return-time information is workload-specific and vanishes under measured tool latencies, and a published duration estimator, borrowed verbatim, misses the accuracy threshold by a margin that four more orders of sample magnitude do not close.
% CLAIMS 2.5, 2.6
% CLAIMS 2.7
% CLAIMS 2.8, 2.9

That leaves one reachable lever: a \textbf{compile-time configuration}, which is coordination decided once, in advance, for everybody. We select one from workload \emph{distribution} statistics and the uncalibrated model alone, with no device measurement in the selection loop, apply it with a seven-minute recompile, and confirm the recovery on two independent channels registered before measurement.
% CLAIMS 2.6, 3.1
% CLAIMS 3.2, 3.3, 3.4

Finally we ask where the lever stops. Pushing \texttt{batch\_size} from 8 to 32 shows the gain \textbf{saturating at 16} and going flat, for a reason the data makes visible: the survival rate has reached 100 \%, so a larger pool has no cache left to save, and the widest compiled rung is never selected at this concurrency, so its higher step cost is never charged either. The KV ceiling on this device lies near \texttt{B = 46}, three times beyond where the gain ends --- \textbf{the optimal configuration is set by the workload distribution, not by what the hardware can hold.}

\subsection{Contributions}

\begin{enumerate}
  \item A device-level decomposition of the return-arrival process into three mechanisms, with the first established \textbf{causally by a recompile intervention}.
  % CLAIMS 1.5, 1.6
  \item A step-level substrate model with \textbf{zero fitted parameters} that passes preregistered out-of-sample, intervention and workload-transfer gates.
  % CLAIMS 1.14–1.17
  \item An information decomposition showing that most of the available headroom is \textbf{coordination}, which per-session runtime policy cannot reach even with omniscient knowledge.
  % CLAIMS 2.5, 2.6
  \item A compile-time configuration selected from distribution statistics alone and \textbf{confirmed on device} against preregistered predictions, together with the saturation curve that bounds it.
